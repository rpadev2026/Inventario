# Módulo Recetas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Agregar el módulo Recetas (fichas técnicas con ingredientes que son productos o sub-recetas) con costo total y por porción calculado desde `"CostoUnitarioBase"`.

**Architecture:** Migración `0019` con tablas `Recetas`/`RecetaDetalles`, triggers de reglas, RPC `guardar_receta` (transaccional) y `calcular_receta` (recursiva, devuelve jsonb). La app (`/recetas`) sigue el patrón de Productos: server action con Zod → RPC; páginas listado/ver/crear/editar; vista previa de costo con lógica pura en TypeScript.

**Tech Stack:** Next.js 16 (App Router), TypeScript, Supabase (Postgres), Zod, Vitest + PGlite, Playwright-core para el recorrido.

**Spec:** `docs/superpowers/specs/2026-10-08-recetas-design.md`

## Global Constraints

- Columnas PascalCase entre comillas; enlaces a maestros por CÓDIGO (`UnidadesMedida."Codigo"`); claves `bigint generated always as identity`.
- Auditoría como `Productos`: `IdUsuarioCreacion`, `FechaRegistroCreacion`, `IdUsuarioModificacion`, `FechaRegistroModificacion`; trigger `trg_mod ... set_modificacion()`; RLS activo sin políticas, `revoke all ... from anon, authenticated`.
- Columna del código de receta: **`"CodigoReceta"`** (opcional, único, en MAYÚSCULA; vacío = null). `"Nombre"` único, MAYÚSCULA.
- Merma: `bruto = neto × (1 + merma)`, `"PorcentajeMerma"` es fracción (0,25 = 25 %), `>= 0`, `numeric(6,4)`.
- `"Cantidad"` `numeric(10,3)` > 0 (defecto 1); `"PorcionNeta"` `numeric(10,3)` > 0; `"RendimientoPorciones"` `numeric(8,2)` > 0 (defecto 1); `"RendimientoCantidad"` `numeric(14,3)` > 0.
- Errores de negocio en SQL con `raise exception '<mensaje en español>'` (código `P0001`); la app solo muestra esos mensajes.
- Nueva migración numerada `0019_recetas.sql`; actualizar `supabase/tests`. Instalar dependencias con `--legacy-peer-deps` (no se esperan nuevas).
- Permisos nuevos `recetas.ver` y `recetas.gestionar` (catálogo en `lib/auth/permisos.ts`; el rol Compras recibe ambos por `RolesPermisos` en la migración; los permisos NO viven en una tabla de catálogo).
- Commits con `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`; `git add` con rutas explícitas; rama `feat/recetas`.
- UI: solo clases de `app/tema.css` (`card`, `btn`, `input`, `table`, `badge`…); formularios con `components/app/field.tsx`; selectores con `components/app/combobox.tsx`; líneas apiladas en celular (`line-grid`).

## Review Focus

- Receta que se incluye a sí misma o forma un ciclo indirecto (A→B→A) debe rechazarse, y `calcular_receta` nunca debe recursar sin fin (Task 1 y 3).
- Ingrediente sin costo (producto sin factura) no debe romper el cálculo: línea «sin costo» y receta «incompleta» (Task 3).
- Cambiar `RendimientoUnidad` de una sub-receta ya usada a otra familia, o desactivarla estando en uso, debe bloquearse (Task 1).
- Cambiar unidad base/factor de una unidad usada por recetas, o la unidad base de un producto usado en recetas, debe bloquearse (Task 1).
- Guardar con errores a mitad de camino no debe dejar la receta con detalles a medias (Task 2).
